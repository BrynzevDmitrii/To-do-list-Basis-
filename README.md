# Заметки

Небольшое SPA-приложение для заметок с чек-листами: создание, редактирование,
отметка выполненных пунктов, отмена/повтор изменений и восстановление
несохранённых правок после случайной перезагрузки страницы.

## Возможности

- **Заметки с чек-листом** — название + список пунктов с отметкой "выполнено"
- **Undo/Redo** — `Ctrl+Z` / `Ctrl+Shift+Z` работают глобально на странице
  редактирования и не мешают нативной отмене ввода внутри текстовых полей.
  История ограничена 50 шагами и хранит не полные копии заметки, а компактные
  diff-патчи между состояниями
- **Автосохранение черновика** — незафиксированные изменения переживают
  случайную перезагрузку страницы; при возврате предлагается восстановить их
- **Синхронизация между вкладками** — если заметка удалена в другой вкладке,
  открытая здесь страница редактирования корректно об этом сообщает, а не
  падает
- **Подтверждения через модальные окна** — без `alert()`/`confirm()`; свои
  модалки с focus-trap, закрытием по `Escape` и полной работой с клавиатуры
- **Адаптивная вёрстка** — мобильный и десктопный вид
- Уведомления об успешных действиях (сохранение и т.д.)

## Технологии

- [Nuxt 4](https://nuxt.com) (режим SPA, `ssr: false`) + Vue 3 + TypeScript
- [Pinia](https://pinia.vuejs.org) — хранилище заметок и уведомлений
- SCSS — вся вёрстка и компоненты собственные, без UI-библиотек
  (Vuetify/PrimeVue/Element и т.п.)
- [Vitest](https://vitest.dev) — юнит-тесты бизнес-логики (история изменений,
  сторы, работа с `localStorage`)
- Данные хранятся в `localStorage` браузера — бэкенда у проекта нет

## Быстрый старт

### Через Docker (рекомендуется)

```bash
# режим разработки с hot-reload, http://localhost:3000
docker compose up dev

# продакшен-сборка (статика через nginx), http://localhost:8080
docker compose up app
```

### Локально, без Docker

Требуется Node.js ^22.18.0 или >=24.11.0 (см. [Ограничения](#ограничения)).

```bash
npm install
npm run dev        # http://localhost:3000
```

## Скрипты

| Команда | Назначение |
|---|---|
| `npm run dev` | Dev-сервер с hot-reload |
| `npm run build` | Продакшен-сборка (серверный бандл) |
| `npm run generate` | Статическая сборка (то, что использует Docker prod-образ) |
| `npm run preview` | Локальный просмотр собранного `generate`-вывода |
| `npm run typecheck` | Проверка типов (`nuxt typecheck`) — использовать именно её, не голый `vue-tsc`, иначе тестовые файлы не проверяются |
| `npm test` | Юнит-тесты (Vitest), однократный прогон |
| `npm run test:watch` | Юнит-тесты в watch-режиме |

## Структура проекта

```
app/
├── components/     # переиспользуемые компоненты (список, чек-лист, модалка, тосты...)
├── composables/     # переиспользуемая логика: undo/redo, черновики, тосты, отслеживание удаления
├── stores/          # Pinia-сторы: notes (заметки), toast (уведомления)
├── pages/           # index.vue — список заметок, [id].vue — редактор
├── utils/           # diff/patch для истории изменений, безопасная работа с localStorage
└── types/           # общие TypeScript-типы проекта
```

Разделение между `composables/` и `stores/`: в `stores/` — то, что реально
общее состояние на всё приложение (список заметок, очередь уведомлений); в
`composables/` — переиспользуемая логика, у которой при каждом вызове своё
independent-состояние (история undo/redo конкретной сессии редактирования,
черновик конкретной заметки).

## Тестирование

```bash
npm test
```

Юнит-тестами покрыта бизнес-логика, а не компоненты (вёрстка проверялась
вручную и через E2E-сценарии в процессе разработки): diff/patch-алгоритм
истории изменений, лимит и обрезка истории в 50 шагов, сторы `notes`/`toast`,
безопасное чтение/запись `localStorage`, отслеживание удаления заметки из
другой вкладки, автосохранение и восстановление черновика.

## Ограничения

- **Нет бэкенда** — все данные живут в `localStorage` конкретного браузера на
  конкретном устройстве. Между устройствами/браузерами ничего не
  синхронизируется.
- **Версия Nuxt зафиксирована на `4.4.2`** (а не `^4.0.0`). В `4.4.4`/`4.4.5`
  есть регрессии, из-за которых dev-сервер падает именно в SPA-режиме
  (`ssr: false`) — см. [nuxt/nuxt#35072](https://github.com/nuxt/nuxt/issues/35072)
  и [nuxt/nuxt#34957](https://github.com/nuxt/nuxt/issues/34957). Прод-сборку
  эти баги не затрагивают.
- **Предупреждение `EBADENGINE` при установке** — часть транзитивных
  зависимостей просит Node `^22.18.0` или `>=24.11.0`; на более старых/средних
  версиях (например, v24.0.0) npm выводит предупреждение, но на работу
  приложения это не влияет.
- **UI-библиотеки не используются осознанно** — вся вёрстка и модальные окна
  написаны с нуля на SCSS.
- **SPA, без серверного рендеринга** — не подходит для сценариев, которым
  нужен SEO или отдача контента без выполнения JS на клиенте.
